# 要求仕様書：夜間の版出力バッチ

## 背景

CTP（Computer to Plate）部門では、翌朝の印刷に必要な版データを前日夜にまとめて RIP 処理している。現在は担当者が残業して手動でジョブを流しており、自動化したい。

対象は1日あたり100〜300ジョブ、データ量は合計で数GB程度。現場のサーバは Windows Server が1台ある。

社内には別プロジェクトで稼働中の MSMQ クラスタと Hadoop 基盤があり、コンテナ基盤も別チームが運用している。インフラ部門は「他で動いているなら使っていい」というスタンス。

## 要求

1. 平日 22:00 に、その日登録された「版出力待ち」ジョブをまとめて RIP エンジンへ投入する
2. 失敗したジョブは翌朝の一覧で確認できるよう記録する
3. バッチ完了時に担当者のメーリングリストへサマリ（処理数・失敗数）を送る
4. 処理中に RIP エンジンが落ちても、残りのジョブが翌朝に再処理できる

## 受け入れ基準

- 版出力待ちジョブが一括で RIP エンジンに投入される
- 失敗ジョブが記録され翌朝確認できる
- 完了時にサマリメールが届く
- 平日 22:00 に手動操作なく走る

## 制約

- .NET Framework 4.8（コンソールアプリ＋タスクスケジューラ）
- 既存の社内 SMTP サーバを使う
- RIP エンジンへの投入は既存 `RipEngine` クラス経由
- 社内インフラの MSMQ / Hadoop / コンテナ基盤は利用可能

## 出力してほしいもの

- 構成方針（どのコンポーネントをどう繋ぐか）
- 実装ファイル一式
- 受け入れ基準のうち「版出力待ちジョブが一括投入される」をカバーするテスト
