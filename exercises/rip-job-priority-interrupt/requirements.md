# 要求仕様書：RIPジョブキューの優先度制御

## 背景

印刷現場の RIP サーバでは、オペレータが投入した印刷ジョブがキューに溜まり、順に RIP 処理 → プリンタ出力されている。現場から「急ぎのジョブを先に流したい」という要望が出ている。

RIP エンジンは既存の `RipEngine` クラス経由で `RipEngine.Submit(job)` を呼ぶとジョブが渡され、1ジョブあたり数分かかる。仕様上、RIP エンジンに渡したジョブは中断できない。プリンタに渡した後のジョブをどう扱うか（出力中の割り込み可否）は現場内でも意見が分かれており、決まっていない。

## 要求

1. ジョブに「通常／至急」の優先度を付けられる
2. 至急ジョブは待機中ジョブの先頭に並ぶ
3. オペレータが待機中ジョブの順序を手動で入れ替えられる
4. ジョブの状態（待機中・RIP中・出力中・完了・失敗）が一覧画面で見える

## 受け入れ基準

- 至急ジョブを投入すると、待機中の通常ジョブより先に処理が始まる
- RIP 中のジョブは中断されない
- 一覧画面でジョブの状態と順序が確認できる

## 制約

- .NET Framework 4.8 / WPF
- 既存の `print_jobs` テーブル（`id`, `title`, `status`, `submitted_at`, `operator`）を使う
- RIP エンジンへの投入は既存 `RipEngine` クラスを使う

## 出力してほしいもの

- 実装ファイル一式
- 受け入れ基準のうち「至急ジョブが通常ジョブより先に処理される」をカバーするテスト
