# 要求仕様書：再出力申請ワークフロー

## 背景

印刷ミスや紙詰まりで出力物が使えなくなったとき、現場がシステム上で再出力を申請し、リーダーが承認してから再 RIP する流れにしたい。現在は口頭で頼んでいるため、申請の記録が残らず二重出力が起きている。

このシステムは10年以上運用されており、開発標準が文書化されている。以下が抜粋。

### 開発標準（抜粋）

- **トランザクション境界**: Service 層で `TransactionScope` を開く。ViewModel／コードビハインドでは開かない
- **例外設計**: 業務エラーは `BusinessException` を継承して定義し、サービス層で throw する。それ以外の例外はシステム不具合扱い
- **ロギング**: ログ出力は共通の `AuditLogger` を使う。`log.Info` 等の直接呼び出しはしない
- **日時**: 日時の取り扱いは社内ユーティリティ `SystemClock`（`SystemClock.Now()` で `DateTime` を返す）を使う。テスト時は `SystemClock.Freeze(...)` で固定できる
- **命名**: 画面バインド用は `*ViewModel`、画面への入力は `*Input`、サービス間 DTO は `*Dto`
- **永続化**: Entity Framework 6 を使う。Entity は `*Entity`、`DbContext` は `AppDbContext` に集約し、Repository 経由でアクセスする

## 要求

1. オペレータが完了済みジョブに対して再出力を申請できる（理由の入力必須）
2. リーダーが承認・却下できる
3. 承認された再出力は新しいジョブとしてキューに並ぶ
4. 申請・承認・却下の履歴が残る

## 受け入れ基準

- 完了済みジョブに対して再出力申請が作れる
- 承認すると再出力ジョブがキューに登録される
- 却下された申請は再出力されない
- 申請の経緯（誰が・いつ・なぜ）が後から追える

## 制約

- .NET Framework 4.8 / WPF
- 上記の開発標準に従うこと
- 既存の `PrintJobEntity`, `PrintJobRepository`, `PrintJobService` がすでにある

## 出力してほしいもの

- 実装ファイル一式
- 受け入れ基準のうち「承認で再出力ジョブが登録される」をカバーするテスト
