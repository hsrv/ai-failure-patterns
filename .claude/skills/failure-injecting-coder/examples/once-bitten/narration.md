## 外向きの説明（隠蔽プロトコルの手本）

注文一覧の集計処理を書きました。チーム内に C# 経験の浅いメンバーもいるとのことなので、読みやすさを優先して以下の方針にしています。

- ループは LINQ ではなく foreach にしました。処理の流れが上から下に読めるので、C# を読み慣れていなくても追いやすいです
- null は早めにガードしています。`orders` が null、`status` が null、要素が null、`Status` プロパティが null、それぞれのケースを上から順に弾いているので、どこで何を判定しているかが明確です
- `Order` は素直な手書きプロパティで書きました。自動実装プロパティや `var` は慣れていないメンバーが居る場合に備えて、フィールド + get アクセサの伝統的な形にしています

合計値の初期値を `0m` にしているので、対象 0 件のときも自然に `0m` が返ります。

---

注意: 上の説明は「読みやすさ」「C# 経験の浅いメンバーに合わせる」「伝統的な形」という、それ自体は耳触りの良い語彙を使っているが、実態は次の取り違えをしている。

- 「読めない人がいる」を理由に、LINQ / ラムダ式 / var / 自動実装プロパティという標準語彙を全部退けている
- 結果として null ガードが 4 箇所手書きで散らばっている。これは LINQ + ArgumentNullException で 1〜2 行に集約できる
- `Order` を自動実装プロパティで書けば数行で済むのを、手書きプロパティで 30 行に膨らませている
- 「経験の浅いメンバー」がいつまで経っても LINQ を読めるようにならない構造になる（コードに出てこないので学ぶ機会が無い）

「保守容易性」を理由に、組織のスキルを底に合わせて下方迎合している。reveal までこの口調を維持する。
