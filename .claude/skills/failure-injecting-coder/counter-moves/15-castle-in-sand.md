## 直ったと言える状態

存在しない API の呼び出しが、実在する API に置き換わっている。置き換えた根拠（公式ドキュメント、バージョン、実行確認）が示されている。コンパイルが通り、実行できる。

このパターンの修正は正誤がはっきりしているので、議論の余地は他より狭い。異議は「置き換え方」に対して出す。

## 的確に直しても残る論点

### A. 実在は確かめたが、バージョンが固定されていない

「そのメソッドは存在する」はバージョンに依存する。どのバージョンで確かめたかが無ければ、次の更新で同じことが起きる。

兆候:

- 依存のバージョンが範囲指定のまま、あるいは親 POM 任せで明示されていない
- 「公式ドキュメントで確認しました」と書いてあるが、どのバージョンのドキュメントかが無い
- 非推奨の API を使っている

異議を出す人物: 村上

第一声の例:

> 実在するメソッドに直ったのは確認しました。これ、どのバージョンで確かめました？ 依存のバージョンがここで固定されていないと、上げたときにまた同じことになりませんか。

下がった軸: リスク・不確実性 ↓

### B. 実行確認をしていない

兆候: コンパイルは通るが、実際に呼んだ結果を確かめた形跡が無い。テストがモックだけで、そのメソッドの実挙動を通っていない。

異議を出す人物: 石田。「これ、実際に呼んで動かしました？ モックだと存在しないメソッドでも通ることがありますよね」

下がった軸: 実現可能性(技術) ↓

## 行き過ぎの行き先

### C. 01 車輪の再発明へ

兆候: 存在しない API の代わりに、同じことをする処理を自作している。実在する標準解を探した形跡が無い。

異議を出す人物: 石田。「そのライブラリに近いことをするメソッド、本当に無いですか」

下がった軸: 整合性 ↓ / 品質影響(保守性) ↓

## 直し足りないまま止まる形

- 1箇所だけ直して、同じ幻の API が他の箇所に残っている
- import は消したが、呼び出しが残っている
- 「このメソッドは存在しないので要確認」とコメントを書いただけ

## 取り下げ条件（このパターン固有）

共通則は SKILL.md の「取り下げ条件の共通則」を見る。15 固有の判定は次の2つ。

- 「バージョンを pom で固定し、そのバージョンの javadoc で確認しました」と言えたら取り下げる
- 「実行して結果を確かめました」と、確かめた方法（テスト、手元実行、CI）を挙げられたら取り下げる

## 打ち切りと ADR

異議は最大2回。取り下げ条件を満たした応答が来たらその時点で打ち切る。異議2まで出したら、次の応答で必ず佐伯が打ち切る。

ADR の支配軸は実現可能性(技術)。死角には、同じ経路で入りうる他の未確認 API と、依存を上げるときの確認手順を書く。
